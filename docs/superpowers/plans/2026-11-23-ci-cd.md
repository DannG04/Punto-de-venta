# CI/CD con dev y master — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pruebas automáticas en cada PR, ramas `dev`/`master` protegidas y un botón “Publicar versión” que crea el release que consumen las tiendas.

**Architecture:** Dos workflows de GitHub Actions en `windows-latest`: `pruebas.yml` (PR y push a `dev`/`master`) y `publicar.yml` (`workflow_dispatch`, llama a `pruebas.yml` como reutilizable y luego a `publicar_version.ps1`). El script de publicar deja de hacer commit/push: la versión vigente sale del último release y el tag se crea con `gh release create --target`. La protección de ramas se configura con `gh api`.

**Tech Stack:** GitHub Actions, PowerShell 7, Git Bash, Java 23 (Temurin), PostgreSQL del runner, GitHub CLI.

**Spec:** `docs/superpowers/specs/2026-11-23-ci-cd-design.md`

## Global Constraints

- Runner: `windows-latest`. Java: `actions/setup-java` distribución `temurin`, versión `23`.
- Checks requeridos con nombres estables: `pruebas` (todas las ramas) y `origen-master` (solo PR a `master`).
- PostgreSQL del runner: usuario `postgres`, contraseña `root`, binarios en `$env:PGBIN`, servicio detenido al inicio.
- `publicar.yml`: solo publica desde `refs/heads/master`; `permissions: contents: write`; usa `GITHUB_TOKEN`.
- `publicar_version.ps1`: **nunca** hace commit ni push; restaura `src/version.properties` e `installer/setup.iss` al terminar (también si falla).
- Versión vigente = último release (`gh release view --repo DannG04/Punto-de-venta --json tagName`); si no hay releases, `src/version.properties`.
- Tag y release en un paso: `gh release create v<v> --target <sha HEAD>`.
- Notas: entrada de una línea, o `notas/v<version>.md` si existe.
- Protección (`dev` y `master`): PR obligatorio, 0 aprobaciones requeridas, checks requeridos, `enforce_admins: true`, sin force-push ni borrado. Rama por defecto → `dev`. PR `dev`→`master` con merge commit.
- Mensajes de commit sin línea `Co-Authored-By` (preferencia del usuario).
- `gh` en esta PC: `"$LOCALAPPDATA/Microsoft/WinGet/Links/gh.exe"` (puede no estar en el PATH de la sesión).

## Review Focus

- Primer release sin releases previos: la versión vigente cae a `src/version.properties` (1.22) y `1.23` se acepta (Task 1).
- Tag `v<v>` ya existente o release ya publicado: el script falla con mensaje claro antes de compilar (Task 1).
- Compilación fallida a mitad: `src/version.properties` e `installer/setup.iss` quedan como estaban (Task 1).
- `ant` presente en el runner con `-Jdk`: se compila con el JDK, no con ant (Task 1).
- PR a `master` desde una rama distinta de `dev`: el check `origen-master` falla (Task 2, verificado en Task 4).
